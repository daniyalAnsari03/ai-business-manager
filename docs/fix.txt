1. Stored-token permissions check (business 338f48b5..., platform=facebook,
   external_account_id=118212491230491 "D&N Collection"):

   GET /debug_token (input_token = stored token, access_token = app_id|secret):
   - type: USER (it is a USER access token, not a System User token)
   - is_valid: true
   - scopes include: pages_show_list, pages_read_engagement,
     pages_manage_posts, business_management (+ public_profile)
   - granular_scopes.pages_manage_posts target_ids include 118212491230491.
   => The reconnect DID capture pages_manage_posts. The token is NOT stale.

   GET /me/permissions: pages_manage_posts = granted (all permissions granted).

2. Raw publish reproduction on the same stored token:
   - resolvePageAccessToken (GET /me/accounts) -> returned a valid Page-scoped
     token for 118212491230491.
   - POST /118212491230491/feed with the PAGE token  -> 200
     {"id":"118212491230491_1015484321517532"}
   - POST /118212491230491/feed with the STORED (USER) token -> 403 OAuthException
     code 200: "...If posting to a page, requires both pages_read_engagement and
     pages_manage_posts with a PAGE token..."
   - POST /photos (real photo draft d03c7d57) with PAGE token -> 200
     {"id":"1015485318184099","post_id":"118212491230491_1015485354850762"}
   - POST /feed for the previously-failed draft 78e8b68a with PAGE token -> 200.
   => Page publishing WORKS with a page token; a USER token is rejected with
      403/code 200 EVEN WHEN it has pages_manage_posts.

3. ROOT CAUSE: Meta requires a PAGE-scoped token for /page/feed and
   /page/photos posts. The deployed publisher was signing posts with the stored
   USER token (the old facebook-publish.ts used connection.access_token
   directly), so every publish returned 403/code 200 and the UI collapsed it to
   the generic "couldn't be published" message. The reconnect / permission were
   never the (remaining) problem.

4. FIX (in the working tree):
   - app/api/marketing/oauth/callback/route.ts: store the PAGE token
     (page.page.accessToken from discoverPage) instead of the USER code token.
   - lib/marketing/facebook-publish.ts: resolve the page token at publish time
     via resolvePageAccessToken and use it (falling back to stored only when
     unresolvable); classify OAuthException code 200 naming pages_manage_posts
     as permission_missing.
   - lib/marketing/meta-oauth.ts: export resolvePageAccessToken; surface
     Page accessToken from discoverPage; facebook scope list now includes
     pages_manage_posts.
   - components/marketing/marketing-view.tsx: map permission_missing to the
     honest localized "publishPermissionMissingMessage" instead of the generic
     failure message.
   - All verified: tsc --noEmit clean; live Graph API reproduction shows page
     publish succeeds for text and photo posts, and for a previously-failed
     draft.

   NOTE: these files were uncommitted in the working tree at diagnosis time —
     the running deployment used the OLD committed code that lacked the page-token
     fix, which is exactly why the Publish button still failed after reconnect.
     Commit + redeploy for the fix to take effect.
