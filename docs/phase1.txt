=== WHAT TO BUILD IN THIS PHASE ===

1. DATABASE (Supabase migrations)

Create new tables, following the exact same patterns already used in
this project (same RLS approach as products/customers/orders — check
those existing tables/migrations first and mirror the pattern exactly,
do not invent a different security model):

- `social_posts` — id, business_id, product_id (nullable), platform,
  caption, media_url, status (draft/scheduled/published/failed),
  scheduled_at, published_at, created_at, updated_at.
- `ad_campaigns` — id, business_id, social_post_id (nullable),
  platform, budget_amount, spent_amount, status
  (draft/active/paused/completed), goal (whatsapp/website/profile),
  created_at, updated_at.
- `marketing_wallet` — id, business_id, balance, monthly_budget_cap,
  created_at, updated_at. (Balance will start at 0 — no payment logic
  yet, just the column existing.)
- `connected_accounts` — id, business_id, platform
  (instagram/facebook/google_ads/whatsapp), status
  (not_connected/connected), account_label (nullable, for display),
  created_at, updated_at. (No real OAuth tokens yet — just the
  schema and a status field defaulting to not_connected.)

Every table MUST have RLS policies scoped by business ownership,
exactly matching the existing pattern used for products/customers/
orders in this project. Do not weaken or skip RLS for these new
tables under any circumstance — this violates AGENTS.md Section 10 and
Section 24.

2. SIDEBAR — NEW "MARKETING" TAB (SHELL ONLY)

- Add "Marketing" to the existing sidebar navigation, in the same
  style/position pattern as Products/Customers/Orders/Settings.
- The page it links to should show:
  - The 3 metric cards (Posts this week, Ad spend, Sale from ads) —
    reading real values from the new tables (which will be empty/zero
    right now — that is correct and expected for this phase, do NOT
    fill them with fake/mock numbers).
  - An empty-state "Activity" section with a proper empty state
    message (per AGENTS.md Section 27 — clear, non-technical language,
    in the user's selected language) since there is no activity data
    yet.
  - The "Automation mode" toggle UI (Needs approval / Full auto) —
    visually present, but it does not need to do anything functional
    yet (no backend behavior tied to it in this phase — note this
    clearly in your report).
- This page must respect the existing English/Roman Urdu language
  switcher (AGENTS.md Section 19) — every label, heading, and empty
  state message must pull from the same language system already used
  elsewhere in the app. Do not hardcode English or Roman Urdu text
  directly in components.

3. SETTINGS — NEW "MARKETING SETTINGS" SECTION (SHELL ONLY)

- Add a new section inside the existing Settings page: "Marketing
  settings" (or the correctly localized label per the language
  system).
- List Instagram, Facebook Page, Google Ads, WhatsApp number — each

- Add a "Monthly ad budget cap" input field that reads/writes to the
  marketing_wallet table's monthly_budget_cap column. This one CAN be
  functional in this phase (it's just a number save, no payment logic
  involved) — saving it should actually persist to Supabase.

4. DESIGN CONSISTENCY — NON-NEGOTIABLE

Every screen built in this phase must exactly follow AGENTS.md's
locked design rules:
- Fonts: Ferly for any large display heading, Inter for all normal UI
  text (labels, buttons, body). No other fonts.
- Colors: obsidian/deep black, deep charcoal, deep emerald, off-white,
  with emerald-to-black glow accents — matching the existing app's
  visual language exactly. Do not introduce new colors, gradients, or
  a different visual style for this module.
- Cards must have the same depth/shadow/glow treatment as existing
  cards elsewhere in the app — not flat rectangles.
- Both dark mode (primary) and light mode must work correctly and
  maintain the same premium visual language (AGENTS.md Section 18).
- Any animation must use Framer Motion, be subtle and purposeful, and
  respect reduced-motion preference (AGENTS.md Section 22).

Before writing any UI code, look at how the existing Products or
Customers page is styled and literally reuse those same components/
classes/patterns — do not create a parallel styling approach.
