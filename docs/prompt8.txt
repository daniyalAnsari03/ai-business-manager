# STEP 3 — SPEECH-TO-TEXT

Implement speech recognition using a free browser/device-supported approach where practical.

Do NOT introduce a paid speech API.

The implementation should:

* request microphone permission only when the user starts voice input
* clearly communicate microphone permission state
* start listening when activated
* stop listening when requested
* capture recognized text
* send recognized text to the existing AI agent
* handle unsupported browsers gracefully

Do not activate the microphone automatically.

The user must intentionally press the voice button.

---

# STEP 4 — TEXT-TO-SPEECH

Implement free browser/device text-to-speech where practical.

Do NOT introduce a paid voice API.

The AI response should be speakable.

The flow should be:

AI response received
    ↓
Display response
    ↓
Speak response

Provide controls to:

* start speaking
* stop speaking
* replay response where appropriate

Do not automatically speak unexpectedly if the user has disabled voice behavior.

---

# STEP 5 — LANGUAGE BEHAVIOR

Voice must respect the application's selected language.

### English mode

User speaks English.

AI understands English.

AI responds in English.

Text-to-speech uses an appropriate English voice when available.

### Roman Urdu mode

User speaks Roman Urdu where browser/device speech recognition supports it.

AI receives the recognized text.

AI responds in Roman Urdu.

Text-to-speech should attempt an appropriate Urdu-compatible voice where available.

IMPORTANT:

Roman Urdu is written using Latin characters.

Do NOT force the AI response into Urdu/Arabic script when the user has selected Roman Urdu.

Example:

User:

"Mera stock check karo"

AI:

"Bilkul, aapke paas 12 products hain aur 3 products ka stock kam hai."

# STEP 14 — MICROPHONE PERMISSIONS

Microphone permission must be handled responsibly.

Requirements:

* do not request microphone permission on page load
* request only after explicit user interaction
* show a clear explanation if permission is denied
* provide retry
* handle unavailable microphone
* handle browser restrictions
* stop microphone access when listening ends

Do not continuously keep the microphone active.

# STEP 15 — ERROR HANDLING

Handle:

* microphone permission denied
* microphone unavailable
* browser speech recognition unavailable
* speech recognition timeout
* no speech detected
* speech recognition error
* AI request failure
* Gemini provider failure
* all Gemini providers unavailable
* text-to-speech unavailable
* unsupported language voice
* network failure

Messages must be simple.

Do NOT expose technical errors such as:

"HTTP 429"

or:

"Provider adapter exception"

Instead show something understandable.

Example:

"AI abhi available nahi hai. Thori dair baad dobara try karein."
