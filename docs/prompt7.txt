# STEP 4 — GEMINI MULTI-PROJECT FAILOVER

IMPORTANT LOCKED REQUIREMENT:

We want to support multiple Gemini API keys where each key belongs to a DIFFERENT Google AI Studio/Google Cloud project.

Do NOT assume multiple keys from the same Google project create additional independent quotas.

The architecture must treat each configured key as a separate provider configuration.

Example:

GEMINI_API_KEY_1
GEMINI_API_KEY_2
GEMINI_API_KEY_3
GEMINI_API_KEY_4

These may belong to separate legitimately configured Gemini projects.

Implement a server-side Gemini provider/router capable of:

1. Trying the primary Gemini configuration.
2. Detecting appropriate rate-limit/quota failures.
3. Automatically moving to the next configured Gemini configuration.
4. Continuing until a valid response is obtained.
5. Returning a clear error if all configured providers fail.

Conceptually:

Gemini Provider 1
        ↓
      429/quota
        ↓
Gemini Provider 2
        ↓
      429/quota
        ↓
Gemini Provider 3
        ↓
      success

Do NOT implement this as a way to circumvent Google's policies or artificially bypass limits.

This is a legitimate provider failover architecture.

Do NOT create, register, or generate Google projects automatically.

The application only consumes the configured credentials.
