**DO NOT reimplement Groq from scratch.**

The task now is to **diagnose and FIX the runtime failover behavior**.

The required final behavior is:

```text

      ↓

      ↓ 429 / retryable failure
Gemini 2
      ↓ 429 / retryable failure
Gemini 3
      ↓
   SUCCESS
      ↓

```

The user must NOT see a quota error if Gemini 3 is available.

If all Gemini projects fail:

```text
Gemini 1 ❌

Gemini 6 ❌

Gemini 8 ❌

     GROQ
       ↓
   SUCCESS
       ↓

```

The user must NOT see a quota error if Groq successfully handles the request.

Only when:

```text
Gemini 1–8 ❌
      +
Groq ❌
```

may the application return the final provider/quota error.

# STEP 4 — FIX GEMINI FAILOVER

The Gemini router must treat retryable provider failures as **failover conditions**, not final user errors.

At minimum correctly handle:

* HTTP 429
* quota exhaustion
* retryable 5xx
* network failures
* timeout
* temporary provider unavailable

For example:

```text
Gemini 1 → 429
```

must mean:

```text
try Gemini 2
```

NOT:

```text
return quota error
```

Continue until:

* a Gemini slot succeeds, OR
* all Gemini slots fail.
